# Work modes

| Mode | User intent | Minimum outcome |
| --- | --- | --- |
| Draft | Explore or create an editable design | Editable artifacts plus explicit assumptions and Prototype gaps |
| Prototype | Decide whether a low-risk sample is worth building | Current readback, engineering review, rating, blockers/advisories, persistence and EDA gates |
| Manufacturing Release | Prepare controlled production outputs | Defined as a future governance tier; not claimed complete in v0.1.0-alpha |

Ordinary-language requests remain the user interface. Project, page, object, library, approval, and transaction identifiers are adapter details and are never required as user input.

When a request is underspecified, make bounded assumptions only where they do not conceal an electrical, thermal, protection, mechanical, or interface risk. Record all assumptions in the review.
